# 架构与协议

## 1. 数据流

```
Surface(Arch)                主机(Windows)
─────────────                ─────────────
/dev/input/event3
  (MT-B, 16 指)
      │ evdev, 独占(grab)
      ▼
panel.py
  ├ 原始坐标 0..9600 / 0..7200
  ├ 归一化 → 旋转 → 逻辑像素 (1014×1520)
  ├ 极坐标映射到 583×583 分区图
  ├ 取点 + 圆周 12 点取色 → 分区集合
  └ 打包 9 字节帧
      │ TCP 23333（NODELAY）
      ▼
                          bridge.py
                            ├ 写线程 1000 Hz 刷当前帧 → COM2
                            ├ 读线程解析游戏 6 字节命令
                            └ 状态端口 23334（给 HUD）
                                  │
                            虚拟串口对: COM2 ⇄ COM1
                                  │
                              majdata DX
                                (GameApp)
```

反向：游戏往 `COM1` 发 6 字节命令 → `COM2` → 桥接解析 → 回写设置包。
触摸数据只单向流动（面板→游戏），命令只用于握手/启停。

## 2. 数据包格式（与上游逐字节一致）

### 面板 → 游戏：9 字节

```
0x28 '(' + B0 B1 B2 B3 B4 B5 B6 + 0x29 ')'
```

| 字节 | 分区（bit0 起） |
|---|---|
| B0 | A1 A2 A3 A4 A5 |
| B1 | A6 A7 A8 B1 B2 |
| B2 | B3 B4 B5 B6 B7 |
| B3 | B8 C1 C2 D1 D2 |
| B4 | D3 D4 D5 D6 D7 |
| B5 | D8 E1 E2 E3 E4 |
| B6 | E5 E6 E7 E8 |

### 游戏 → 面板：6 字节，`data[3]` 是命令

| 命令 | ASCII | 含义 |
|---|---|---|
| 76 / 69 | `L` / `E` | 停止读取面板 |
| 114 / 107 | `r` / `k` | 设置类，需回写 `[0x28, d1, d2, d3, d4, 0x29]` |
| 65 | `A` | 开始读取（面板激活） |

桥接的实现要点：读到 `r/k` 时**必须原样回写**，否则游戏不认为面板就绪。

## 3. 分区判定为什么用极坐标

上游要求准备一张与屏幕同尺寸的 P 图，把彩图摆在游戏圆环的位置上。
本项目改成：**屏幕点 → 以 (圆心, 半径) 归一化 → 583×583 彩图坐标 → 取色**。

好处：换分辨率、换窗口位置、加 letterbox 都不用重新 P 图，只要重新给圆心+半径。
代价：必须知道圆在屏幕上的位置（用 `detect_circle.py` 从截图里找）。

## 4. 为什么必须独占触屏

不独占的话，触摸会同时被 KWin → Moonlight 当作**鼠标**发给主机，
游戏会收到「鼠标点击」和「触摸板分区」两份输入 → 双触发。

`EVIOCGRAB`（python-evdev 的 `dev.grab()`）后 KWin 收不到事件，问题消失。
代价：面板服务运行期间这台设备不能当普通触屏用，所以 `stop.sh` 必须停服务。

## 5. 时间预算（实测）

| 环节 | 延迟 |
|---|---|
| TCP 局域网 RTT | 2-4 ms |
| 面板采样→发送 | ≤ 1 个 SYN_REPORT（约 8 ms 一帧） |
| 桥接 → 串口 | 1000 Hz 写帧，≤ 1 ms |
| 串流编码+传输+解码 | 约 30-50 ms（Moonlight 显示延迟） |

触摸本身几乎无额外延迟，主要延迟来自串流链路（可在 Moonlight 里看 stats）。
