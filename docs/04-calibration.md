# 分区校准

分区数据来自上游的 **583×583 分区彩图**，本项目用**极坐标反向映射**把它铺到屏幕上的触摸圆上：

```
屏幕触摸点 (x,y) ──以(圆心,半径)归一化──▶ 彩图坐标 (ax,ay) ──取色──▶ 分区名
```

所以只需要两个参数：**圆心** 和 **半径**（外加旋转）。

## 1. 从游戏画面量圆

主机端截图（游戏竖屏 1080×1920），用脚本自动找圆：

```bash
python detect_circle.py shot1.png shot2.png shot3.png
# 输出: 综合 cx=540 cy=1385 r=535
```

> 取 3 张不同界面的截图取中位数更稳（不同画面亮度会干扰梯度）。

## 2. 换算到 Linux 逻辑坐标

```bash
python3 ~/setmap.py --cx 540 --cy 1385 --r 535
```

`setmap.py` 会自动按串流缩放换算并重启 `panel`：

```
k  = 1520/1920 = 0.79167      # 串流在逻辑屏里的缩放
x0 = (1014 - 1080k)/2 = 79.5  # 左右居中
center = (x0 + cx*k, cy*k)
radius = r*k
```

## 3. 在线微调

```bash
python3 ~/setmap.py                    # 显示当前值（含换算回主机的数值）
python3 ~/setmap.py --cy 1380          # 下移
python3 ~/setmap.py --r 560            # 放大
python3 ~/setmap.py --rot 90           # 旋转（0/90/180/270）
python3 ~/setmap.py --art-rot 180      # 只转分区图本身
```

`--rot` 影响「触摸坐标怎么转」，`--art-rot` 影响「分区图怎么摆」，两者正交，
一般的错位先试 `--rot`，扇区整体转了再试 `--art-rot`。

## 4. 用 HUD 判断对错

主机端 `hud.py` 会把当前命中的分区半透明画在游戏画面上（随串流显示）：

* 手指按下 → 对应扇区变亮绿 + 顶部显示分区名
* 亮的位置比你手指偏 → 圆心/半径要调
* 亮的扇区转了一个角度 → `--art-rot`
* 一次点亮 2-3 个相邻区 → `scope` 调小（30 → 24）

## 5. 方向完全反了（上下左右颠倒 180°）

`rotation` 差了 180°：`--rot 90` ↔ `--rot 270` 互换即可。

## 6. 参数速查

| 参数 | 含义 | 典型值 |
|---|---|---|
| `center` | 触摸圆圆心（逻辑像素） | `[507.0, 1096.5]` |
| `radius` | 触摸圆半径（逻辑像素） | `423.5`（主机 535 × 0.79167） |
| `rotation` | 触屏原生 → 逻辑屏旋转 | 竖屏 90 或 270 |
| `art_rotation` | 分区图相对屏幕的旋转 | 0（多数情况） |
| `scope` | 采样半径（583 图坐标） | 30（24 更精准，40+ 更"钝"） |
| `points` | 圆周采样点数 | 12 |
